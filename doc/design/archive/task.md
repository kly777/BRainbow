## 设计思路

任务是抽象的工作单元——任何需要投入时间去做的事情。

围绕三个维度展开：

- **结构**：任务可拆分为子任务（树），也可标记执行顺序（有向无环图）
- **时间**：区分客观可行性、主观计划、实际记录三个层次
- **精力**：预估所需投入

## 状态流转

一个任务经历四个阶段：

```
backlog ──→ active ──→ completed
   │          │           │
   └──────────┴─────→ archived
```

| 状态 | 含义 |
| :--- | :--- |
| **待办** (backlog) | 已录入但尚未决定执行。不参与排程和日历展示 |
| **进行中** (active) | 当前活跃，出现在日历和依赖图中 |
| **已完成** (completed) | 标记完成，记录完成时间 |
| **已归档** (archived) | 从常规视图中隐藏，不再参与任何展示 |

状态可以随时切换：待办激活为进行中，完成后归档。进行中的任务也可以直接归档（放弃）。已归档的任务可以移回待办。

## 结构与依赖

### 父子拆分

大任务 → 小任务，形成树。比如"搬家"拆分为"打包书籍""联系搬家公司""退租清洁"。

后端不做层数限制。前端以可折叠树展示，子任务缩进。

### 执行顺序

B 必须在 A 之后才能开始 → B 依赖 A。

依赖关系独立于父子关系。父任务和子任务可以互相依赖，也可以跨树依赖。系统只保证不出现循环依赖和自依赖。

前端以力导向 DAG 图展示。

## 时间维度

每个任务可挂多个**时间窗口**，分三种语义：

| 类型 | 含义 | 例子 |
| :--- | :--- | :--- |
| **可进行时间** | 客观约束，任务只能在这段时间内执行 | 去图书馆借书，受开馆时间限制 |
| **计划时间** | 主观安排，打算什么时候做 | 计划周三下午两点去 |
| **实际时间** | 执行记录，实际花了多久 | 最终周三下午 2:15-3:40 完成 |

### 约束

- **计划时间必须落在可进行时间范围内**——不能计划在图书馆关门后去借书
- **同类型时间段不重叠**——不能同时计划两件事

可进行时间是任务内在属性，计划时间是排程工具，实际时间是回顾数据。三者分层管理，不混在一起。

### 循环规则

任务可能周期性发生（如"每周一开组会"）。时间窗口可以携带重复规则，但展开功能尚未实现。

## 便捷录入

类似 todo 的快速创建：只需要一个标题，其他字段全部置空或使用默认值。

完整创建允许同时设置描述、父任务、精力预估。

## 筛选与搜索

- 按状态筛选：分别查看待办、进行中、已完成、已归档
- 全文搜索：按标题模糊匹配
- 统计概览：四类状态的计数汇总
