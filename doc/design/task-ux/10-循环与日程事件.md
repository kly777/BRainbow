# 10 · 循环任务与日程事件

> 状态：现行（已实现） · 代码基准：`main@48996cd7`（2026-10-22） · 最后核对：2026-10-22
>
> 本文是 09 之后的后端/数据模型定稿。目标是把“要做什么”和“什么时候做/什么时候有事”拆开：
>
> - **task**：可完成的工作项；
> - **task_block**：为某条 task 预留的时间（feasible / planned）；
> - **calendar_event**：不需要完成的时间（生日、纪念日、节日、会议、假期、航班）。
>
> Todo 是 task 的投影；Calendar 是 task_block + calendar_event 的投影。

## 0. 本轮范围

| 做 | 不做 |
|---|---|
| 循环任务（公历 daily/weekly/monthly/yearly） | 循环任务的农历 UI（引擎支持，界面后续） |
| 生日 / 纪念日（公历 + 农历） | 二十四节气全量（只做清明） |
| 传统节日 10 个（含清明） | 官方放假/调休算法（改为导入） |
| 出生年份 + 周岁 | 虚岁 |
| 公历出生日期 → 农历换算辅助 | 事件提醒的浏览器推送 / 邮件 |
| 应用内“未来 7 天” | 实际用时（actual 块已移除） |
| `calendar_event` 独立于 task | 事件与 task 的显式关联表 |
| `task_block.fixed`（固定安排） | 新建 `task_block` 取代 `time_window`（v26 迁移后删除旧表，见 §7） |

## 1. 领域模型

```
task_series ──生成──> task ──< task_block (feasible | planned)
  │                     │
  │                     ├──< task_tag >── tag
  │                     ├──< task_dependency
  │                     └──< task（子任务）
  │
calendar_event_series ──生成──> calendar_event
```

- **task** 是唯一有完成状态的对象。
- **task_block** 只表示“时间”，`fixed=1` 是固定安排，`end_at IS NULL` 是软计划起点。
- **calendar_event** 没有 `status` / `completed_at`；它不进入 Todo。
- **Todo**：`task` + `next_planned_at`。
- **Calendar**：`task_block(planned)` + `calendar_event`；`feasible` 是可选图层。

## 2. 数据表

### 2.1 `task` 追加列

```sql
series_id     INTEGER NULL REFERENCES task_series(id),
occurrence_on TEXT NULL,   -- 循环实例的本地日期 YYYY-MM-DD
UNIQUE (series_id, occurrence_on)
```

其余列保持不变（`start_at` 暂留，见 §7）。

### 2.2 `task_series`

```sql
CREATE TABLE task_series (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id         INTEGER NOT NULL REFERENCES user(id),
  title           TEXT NOT NULL,
  description     TEXT,
  priority        TEXT CHECK (priority IS NULL OR priority IN ('p1','p2','p3','p4')),
  effort_estimate_minutes INTEGER,
  recurrence_rule TEXT NOT NULL,          -- JSON，见 §3
  timezone        TEXT NOT NULL DEFAULT 'Asia/Shanghai',
  starts_on       TEXT NOT NULL,          -- 本地日期
  due_time_minutes INTEGER,               -- 本地钟点；NULL = 全天
  next_occurrence_on TEXT,                -- 下一次生成日期（anchor=due 用）
  archived_at     TEXT,
  created_at      TEXT NOT NULL,
  updated_at      TEXT NOT NULL
);
```

### 2.3 `calendar_event_series`

```sql
CREATE TABLE calendar_event_series (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id         INTEGER NOT NULL REFERENCES user(id),
  preset_key      TEXT,                   -- festival.spring_festival，防重复订阅
  title           TEXT NOT NULL,
  notes           TEXT,
  kind            TEXT NOT NULL CHECK (kind IN ('birthday','anniversary','festival','event')),
  calendar        TEXT NOT NULL CHECK (calendar IN ('gregorian','lunar','solar_term')),
  month           INTEGER,
  day             INTEGER,
  term            TEXT,                   -- 仅 qingming
  leap_policy     TEXT CHECK (leap_policy IS NULL OR leap_policy IN ('regular','leap','skip')),
  missing_day_policy TEXT NOT NULL DEFAULT 'last_day'
                  CHECK (missing_day_policy IN ('skip','last_day','next_month_first_day')),
  born_in_leap_month INTEGER NOT NULL DEFAULT 0,
  since_year      INTEGER,                -- 生日=出生年；纪念日=起始年
  since_on        TEXT,                   -- 公历出生/起始日期
  all_day         INTEGER NOT NULL DEFAULT 1,
  busy            INTEGER NOT NULL DEFAULT 0,
  upcoming_days   INTEGER NOT NULL DEFAULT 7,
  timezone        TEXT NOT NULL DEFAULT 'Asia/Shanghai',
  starts_on       TEXT NOT NULL,
  archived_at     TEXT,
  created_at      TEXT NOT NULL,
  updated_at      TEXT NOT NULL,
  CHECK (
    (calendar = 'solar_term' AND term IS NOT NULL AND month IS NULL AND day IS NULL)
    OR
    (calendar IN ('gregorian','lunar') AND month IS NOT NULL AND day IS NOT NULL AND term IS NULL)
  )
);
```

### 2.4 `calendar_event`

```sql
CREATE TABLE calendar_event (
  id             INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id        INTEGER NOT NULL REFERENCES user(id),
  series_id      INTEGER NULL REFERENCES calendar_event_series(id),
  occurrence_on  TEXT,                   -- 本地日期 YYYY-MM-DD
  occurrence_year INTEGER,               -- 公历年或农历年，算周岁
  title          TEXT NOT NULL,
  notes          TEXT,
  start_at       TEXT NOT NULL,
  end_at         TEXT NOT NULL,
  all_day        INTEGER NOT NULL DEFAULT 1,
  busy           INTEGER NOT NULL DEFAULT 1,
  kind           TEXT NOT NULL DEFAULT 'event',
  source         TEXT NOT NULL DEFAULT 'manual'
                 CHECK (source IN ('manual','import','recurrence')),
  external_id    TEXT,
  deleted_at     TEXT,
  created_at     TEXT NOT NULL,
  updated_at     TEXT NOT NULL,
  CHECK (end_at > start_at),
  UNIQUE (series_id, occurrence_on)
);
```

全天事件按**本地日期**解释；`start_at`/`end_at` 存本地零点的 UTC 表示，展示只用日期。

### 2.5 `task_block`（替代 `time_window`）

```sql
CREATE TABLE task_block (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER,
  task_id INTEGER NOT NULL,
  kind TEXT NOT NULL DEFAULT 'planned' CHECK (kind IN ('feasible','planned')),
  start_at TIMESTAMP NOT NULL,
  end_at TIMESTAMP,
  fixed INTEGER NOT NULL DEFAULT 0,
  source TEXT NOT NULL DEFAULT 'manual',
  created_at TIMESTAMP DEFAULT (strftime('%Y-%m-%dT%H:%M:%S+00:00', 'now')),
  updated_at TIMESTAMP DEFAULT (strftime('%Y-%m-%dT%H:%M:%S+00:00', 'now')),
  CHECK (end_at IS NULL OR end_at > start_at),
  CHECK (end_at IS NOT NULL OR kind = 'planned'),
  CHECK (fixed = 0 OR (kind = 'planned' AND end_at IS NOT NULL))
);
```

`fixed=1` 只允许出现在 `planned` 且 `end_at` 非空的块上。`actual` 类型不再存在；旧 `time_window` 的 `actual` 行在 v26 迁移时丢弃。

## 3. 循环规则 JSON

统一值对象，task_series 与 calendar_event_series 共用：

```json
{
  "calendar": "gregorian",
  "freq": "weekly",
  "interval": 1,
  "by_weekdays": [1, 3, 5],
  "until": "2027-12-31",
  "count": null
}
```

```json
{
  "calendar": "lunar",
  "freq": "yearly",
  "month": 8,
  "day": 15,
  "leap": "regular",
  "missing_day": "last_day"
}
```

```json
{ "calendar": "solar_term", "term": "qingming" }
```

```json
{ "calendar": "lunar", "special": "new_year_eve" }
```

规则校验：

- `freq` ∈ `daily|weekly|monthly|yearly`；
- `interval >= 1`；
- `by_weekdays` 仅 weekly，值 1..7；
- `calendar=lunar` 时 `month 1..12`、`day 1..30`；
- `calendar=solar_term` 仅允许 `qingming`；
- `until` / `count` 二选一即可，都为 null 表示无限；
- 规则解析失败必须在写入口 400，不得静默降级。

## 4. 农历与清明

- 依赖 `lunar-lite = "1.3.0"`（MIT，支持公历↔农历、闰月、月长、节气基础）。
- 封装在 `calendar/lunar.rs`，领域层只依赖 `LunarConverter` 接口。
- 支持范围：1900–2100；超出范围返回错误，不猜。
- 闰月策略：
  - `regular`：闰月年仍取正月的生日/节日；
  - `leap`：只在闰月存在时取闰月；
  - `skip`：闰月年跳过。
- 小月没有三十：`last_day` 取廿九；`skip` 跳过；`next_month_first_day` 顺延。
- 除夕：`special="new_year_eve"`，取农历年最后一天（廿九或三十）。
- 清明：`calendar="solar_term", term="qingming"`；用 1900–2100 的清明日期表（lunar-lite 只公开立春，不公开全部节气）。
- 换算使用 Asia/Shanghai；跨时区/海外出生属于已知边界，详情里提示人工确认。

## 5. 生成（materializer）

### 5.1 task_series

- `anchor=due`：按规则生成未来 60 天的 `task` occurrence；
- `anchor=completion`：完成当前 occurrence 时生成下一次；
- 唯一键 `(series_id, occurrence_on)` 保证幂等；
- 生成时复制 series 的 title/description/priority/effort；
- 编辑 series：删掉未来**未修改**的 occurrence 再重新生成；已修改/已完成的不动。

### 5.2 calendar_event_series

- 按规则生成未来 24 个月的 `calendar_event`；
- `occurrence_year` 在生成时写入（公历年或农历年）；
- 生日/纪念日的 `since_year` 用于算周岁/周年；
- `GET /calendar/events?start&end` 与 `/calendar/upcoming` 前先补当前范围；
- 修改 series 时重建未来未修改的 occurrence。

### 5.3 调用点

- 创建/更新 series 后立即 materialize；
- 每次读日历/未来 7 天前 `ensure_range`；
- 启动时不跑全量；懒生成足够。

## 6. API

### 6.1 任务序列

```
GET    /tasks/series
POST   /tasks/series
PATCH  /tasks/series/{id}
DELETE /tasks/series/{id}
```

`POST` 请求：

```json
{
  "title": "写周报",
  "priority": "p2",
  "effort_estimate_minutes": 60,
  "recurrence": { "calendar": "gregorian", "freq": "weekly", "interval": 1, "by_weekdays": [5] },
  "starts_on": "2026-10-17",
  "due_time_minutes": 1080
}
```

### 6.2 事件

```
GET    /calendar/events?start=...&end=...
POST   /calendar/events            # 单次事件
POST   /calendar/events/series     # 生日/纪念日/节日/重复事件
GET    /calendar/events/series
PATCH  /calendar/events/series/{id}
DELETE /calendar/events/series/{id}
GET    /calendar/upcoming?days=7
GET    /calendar/lunar/convert?date=YYYY-MM-DD
```

`/calendar/upcoming` 返回：

```json
[
  { "date": "2026-10-20", "kind": "birthday", "title": "妈妈生日",
    "age": 58, "years": null, "days_until": 3, "is_today": false }
]
```

### 6.3 日历读模型

保留现有 `/tasks/calendar` 给旧前端；新增 `/calendar/items?start&end`：

```json
[
  { "item_type": "task_block", "task_id": 1, "block_id": 4, "title": "写周报",
    "start": "...", "end": "...", "all_day": false, "fixed": false, "kind": "planned" },
  { "item_type": "event", "event_id": 9, "title": "妈妈生日",
    "start": "...", "end": "...", "all_day": true, "busy": false, "kind": "birthday" }

```

## 7. 过渡与迁移

`time_window` 模块与物理表**已删除**（v26）：

- 新表 `task_block` 取代它，只保留 `feasible` / `planned`，并新增 `fixed`；
- v26 修复把旧 `time_window` 的 feasible/planned 行搬进 `task_block`，然后 `DROP TABLE time_window`；`actual` 行按设计丢弃；
- `task.start_at` 暂留（旧任务读写仍用它），新 UI 不再用它表示“计划开始”；
- 等前端全部切到 `task_block` API 后，再登记 `legacy` 并删列。

新表是纯增量，老库 reconcile 直接建；真库演练在开发结束后跑。
