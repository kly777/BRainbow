## 决策摘要

本轮已与需求方对齐的六条决策，后续文档均以此为准。

| 决策点 | 结论 | 关键理由 |
|---|---|---|
| 录入必填项 | **只有标题一句话** | 其余属性全部可后加；必填项每多一个，录入转化率就掉一截 |
| 排程自主度 | **只排序 + 给建议，人来落位** | 系统不自动写日历；建议必须带理由且可整批不采纳 |
| 日历形态 | **月网格 + 周/日时间轴双视图** | 月网格做全局概览，时间轴承接排期与拖拽 |
| 新增字段 | **`due_at` / `start_at` / `priority`(p1–p4) / `tags`** | `due` 是排序与"逾期"的地基，重做前完全没有 |
| 录入语法 | **标题行只用显式符号；NLP 只关在第 2 层的日期控件里** | 标题行解析的误报不可控；符号可预测。但 Things 3 已默认支持中文 NLP——它靠"只在专用弹窗里生效"规避误报，这条路可抄 |
| 精力档位 | **本期不做** | 现有 `effort_estimate_minutes`（时长）已够用，精力值属于增量收益 |
| **向后兼容** | **不保留旧设计** | 需求方确认。本项目 schema 是声明驱动的，删表/删列只是登记几行，所以"推翻重来"成本很低；而且 `task` 现有 10 列**没有一列是旧设计遗留物**，实际不丢数据。详见 [08](08-实现路线.md) §0 |
| **工具条密度** | **常驻控件 ≤5 个**，状态/标签/优先级/截止合并进一个「筛选 ⚙」 | P3 的判据同样适用于工具条——控件也是表单项。**活动筛选条件以 chip 常驻按钮旁**，所以信息不丢。详见 [06](06-日历视图.md) §2 |

## 这些结论站在什么证据上

| 主张 | 依据类型 | 强度 |
|---|---|---|
| 录入只用标题就够 | 主流产品（Todoist / TickTick / Things / OmniFocus / RTM）**全部**如此 | 强（跨厂商一致） |
| 渐进披露不超过两层 | Nielsen 明确判据 + NN/g 认知负荷 + GOV.UK one-thing-per-page | 强 |
| 不做自然语言日期解析 | 误报是产品级常态（Todoist 官方自陈）+ 中文解析坑是结构性的（chrono-node 源码） | 强 |
| **不自动落位（P9）** | **算法 aversion**（Dietvorst et al. 2015，已读原文）+ Timefold 的"adoption 而非 math" | 强，但**只对个人场景有间接证据** |
| **拖拽落位** | ⚠️ **最强反例是 Things 3——它故意不做**，日历是只读叠加的预约视图且默认关闭 | 弱（主流产品里唯一的反对意见，已在 [06](06-日历视图.md) §6.1 正面回应） |
| 每条建议都要有理由 | Timefold 四要求之一 + Liao et al. (CHI 2020) 的 question-bank 方法 + Amershi et al. (CHI 2019) | 中（是设计共识，非实验结论） |
| 颜色不能是唯一通道 | **WCAG 1.4.1 失败准则 F81** + MD3 的日期对比度 4.5:1 | 强（规范） |
| 触摸目标 24px | **WCAG 2.5.8** + Apple HIG + **MD3 的 48×48dp** | 强（规范） |
| 网格的键位与焦点模型 | **WAI-ARIA APG Grid / Date Picker Dialog** + MD3 官方键位表 | 强（规范，但两者有出入，见 [07](07-调研附录.md) §3.4） |
| 拖拽反馈契约（3pt 阈值 / 非法目标不高亮 / 优先撤销） | **Apple HIG Drag and drop** | 强（规范） |
| **日期控件里可以做 NLP** | **Things 3**（默认支持中文）+ **MD3**（"打字是第一条用例"） | 强（两个独立官方来源，结论一致） |
| 日期输入"失焦才格式化、禁输入掩码" | **MD3 无障碍规范** | 强（规范，且给了理由） |
| 重叠布局的算法 | 区间图着色，CLRS 第 16 节 | 强（教科书） |
| 周起始日按 locale | **CLDR `firstDay`** | 强（规范） |
| **"日历填满会降低执行力"** | **查不到任何可靠来源** | **已从设计中移除** |

完整的出处、反方意见与"未能核实"清单在 [07](07-调研附录.md)。**§6 那张表同样重要**——本设计有几处明确知道自己缺证据的地方，都在上面写着。

## 一句话的产品主张

当前 task 模块把"录入"和"排程"都当成了填表作业，于是两者都很贵。真实的顺序恰好相反：

1. **先卸下来**。此刻你手上正在想的事，只需要一句话就能离开你的脑子。
2. **稍后再想细节**。截止时间、标签、优先级、放在哪个时间段，都是**未来某个清醒时刻**才有能力回答的问题——此刻强行回答只会得到假数据。
3. **系统代劳排序**。"先做哪件"是一个每天都要重新回答、而且消耗很大的问题。它应该由系统根据你已经给的信息算出来，而不是每次靠你回忆。
4. **人保留落位权**。系统算出"你今天大概该做这三件"和"它们大概能塞进你周二下午的空格"，但绝不擅自改你的日历。采纳是一条点击，不采纳零成本。

这条主张展开成两条主线：**录入侧做减法**（[03](03-录入模型.md)），**排程侧做加法**（[05](05-排序与推荐.md)）。
